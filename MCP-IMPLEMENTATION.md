# RCL Maker MCP on Vercel

The MCP endpoint is integrated into the existing RCL Maker repository and the same Vercel project. The website's existing PDF/DOCX generators remain the source of the documents.

## Deployment

1. Commit and push this repository update to the Git branch connected to the existing Vercel project.
2. In Vercel, create and connect a **Blob** store to this project. This provides `BLOB_READ_WRITE_TOKEN`.
3. In Vercel → Project Settings → Environment Variables, configure:
   - `MCP_API_KEYS` — bearer token entries in `token:user-id` format.
   - `RCL_API_BASE_URL` — production URL of this RCL Maker deployment.
   - `BLOB_READ_WRITE_TOKEN` — created by the connected Vercel Blob store.
   - `MCP_DOWNLOAD_SECRET` — long random secret used to sign expiring download links.
   - `MCP_PUBLIC_BASE_URL` — public production URL, e.g. `https://rcl-three.vercel.app`.
   - `CRON_SECRET` — long random secret protecting the cleanup endpoint.
4. Redeploy the existing Vercel project.
5. Connect the MCP client to `https://your-domain/api/mcp` with `Authorization: Bearer YOUR_TOKEN`.

`api/mcp.js` is the stateless MCP endpoint. `api/download/[token].js` validates a signed five-minute download token and streams the file to the user. `api/cron/cleanup-rcl-files.js` removes expired objects from Blob. A cleanup pass also runs opportunistically when a new document is generated.

## Temporary document delivery

- PDF and DOCX are generated by the same existing RCL Maker API routes used by the website.
- The generated bytes are uploaded to Vercel Blob under a random path in `rcl-temp/`.
- MCP returns a normal HTTPS download link, not an `application/pdf` or DOCX MCP resource. This avoids the Claude client limitation observed with binary MCP resources.
- The download link expires after five minutes. The cleanup cron is scheduled every minute; actual physical deletion depends on successful cron execution and Vercel plan support. Expired links are rejected even if an object has not yet been physically deleted.
- No permanent document archive, database record, or local disk copy is created by this delivery flow.

## Notes

- The website's profile in browser `localStorage` is not automatically accessible to MCP; the user must provide the data in the AI conversation.
- Existing generator routes remain accessible according to their existing behavior. The MCP bearer key protects `/api/mcp`.
- The download endpoint exposes only signed, short-lived links. Treat the Blob token and signing secrets as private environment variables; never put them in frontend JavaScript.
- The cleanup cron requires a Vercel plan that supports the configured one-minute schedule. If the plan rejects that schedule, use a supported cadence; links still expire after five minutes, but physical cleanup may be delayed until the next cleanup run or next document generation.
